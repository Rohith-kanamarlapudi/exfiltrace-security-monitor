Methodology and interpretation

Default service configuration, real watchdog and SQLite, asynchronous detection, 10ms observation polling. USB is a temporary folder and synthetic backend, forced polls exclude physical enumeration/poll interval. Network inputs synthetic; timings exclude capture. CPU includes experiment driver. No UI latency measured.

Latency uses a monotonic clock from immediately before the operation until a matching database record is observed; includes operation duration and query overhead. Timeout: 8 seconds. P95 uses nearest rank. File modifications waited 1.6 seconds after creation to respect the default 1.5-second deduplication window. These results do not assess rapid successive writes or sustained load. Copy trials used different known 65,536-byte contents and renamed destination files. The 0.5-second default stability check contributes to copy-alert delay.

USB insertion/removal trials force a synthetic inventory poll and exclude the default 3-second polling delay and Windows hardware enumeration. Network trials reset a 20-sample baseline (200,000–240,000 bytes) each time and use a documentation IP without transmitting traffic: 250,000-byte known destination; 10,000,000-byte known destination; 1,500,000-byte new destination; 1,000-byte external port 4444; and 1,000-byte new destination on port 443. Network timings are function execution time only.

Negative file controls used 20 unmatched files on the simulated USB. Immediate checks used 0.3-second observation windows; after service shutdown and worker draining, the database contained exactly 20 verified-transfer alerts, all accounted for by the 20 positive copies. It also contained 1 SUSPICIOUS alert from heuristic activity. Therefore report zero extra verified-transfer alerts for these controls, not zero alerts overall or a general zero false-positive rate.

Report-ready results paragraph

In a controlled Windows laboratory evaluation, ExfilTrace recorded all 80 tested filesystem operations and generated verified-transfer alerts for all 20 renamed file copies to a simulated USB mount. Median observable backend delays ranged from 27.37 to 35.61 ms for file events, while median copy-alert delay was 687.05 ms (95th percentile: 714.48 ms). Five synthetic network scenarios matched expected rule behavior across 100 repetitions. Regression testing yielded 189 passes, three unresolved Windows path-lookup test failures and two recovery-tool-dependent skips. Results validate the tested software scenarios; physical USB behavior, live network detection and recovery effectiveness require additional validation.

Reproduction and evidence

From the repository root, use backend/.venv/Scripts/python.exe to run backend/evaluation/run_experiments.py. Run each pytest suite separately with -p no:cacheprovider, a new --basetemp beneath backend/evaluation/work (create the parent first), and --junitxml beneath backend/evaluation/results. Then run backend/evaluation/build_report.py. Preserve previous results before rerunning.

Raw observations: experiments.json. Regression evidence: backend-tests-final.xml and network-tests-final.xml. No application source was modified.
